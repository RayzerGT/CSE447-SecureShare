SecureShare -- Local SQLite Setup (SQLITE_SETUP.txt)

Project : SecureShare (CSE447, BRACU_flex Group 05)
For     : Afnan Satter, Mos. Mahabuba Akter Munia, Razeen Hassan

Follow this to get the project running on your own machine with a local
SQLite database. No database credentials, no MySQL install, no network.

READ THIS FIRST
--------------------------------------------------------------------------------
There is NOTHING to install for SQLite. It ships inside Python itself - there
is no server to start, no username or password, no port. The database is just
one file (db.sqlite3) that Django creates for you in step 5.

We still use the Aiven MySQL server for the PROJECT DEMONSTRATION. That has
not gone away. SQLite is only to make day-to-day development easier. See the
"SWITCHING TO THE SHARED AIVEN DATABASE" section at the bottom.

Total time: about 5 minutes.


================================================================================
STEP 1 -- Check you have Python 3.10 or newer
================================================================================
    python --version

If that prints "Python 3.10.x" or higher, you're fine (the project was built
on 3.13.3). If the command isn't found, try `python3 --version` instead, and
use `python3` everywhere below.

Confirm SQLite is present (it should be - it's part of Python):

    python -c "import sqlite3; print(sqlite3.sqlite_version)"

That should print a version number like 3.49.1. If it errors, your Python was
built without SQLite support, which is rare - reinstall Python from
python.org and it will be included.


================================================================================
STEP 2 -- Get the code
================================================================================
    git clone https://github.com/RayzerGT/CSE447-SecureShare.git
    cd CSE447-SecureShare

If you already cloned it before, just pull the latest:

    git pull


================================================================================
STEP 3 -- Create and activate a virtual environment
================================================================================
    python -m venv .venv

Then activate it:

    Windows (PowerShell) :  .venv\Scripts\Activate.ps1
    Windows (cmd)        :  .venv\Scripts\activate.bat
    macOS / Linux        :  source .venv/bin/activate

You'll know it worked when your prompt starts with (.venv).

You must activate the virtual environment EVERY time you open a new terminal
to work on this project. If a later command says "no module named django",
this is almost always why.


================================================================================
STEP 4 -- Install the Python packages
================================================================================
    pip install -r requirements-sqlite.txt

That file is the normal requirements.txt minus mysqlclient - the one package
that needs a C compiler and the MySQL client libraries, and the usual reason
installs fail on macOS and Linux. You don't need it while you're on SQLite.

    (If you'd rather install everything now, including MySQL support, use
     `pip install -r requirements.txt` instead. On macOS you may first need
     `brew install mysql-client pkg-config`; on Linux,
     `sudo apt install default-libmysqlclient-dev build-essential pkg-config`.
     You will need this before the demonstration - see the bottom section.)


================================================================================
STEP 5 -- Create your .env file
================================================================================
    Windows       :  copy .env.example .env
    macOS / Linux :  cp .env.example .env

Now open .env in a text editor and set SECRET_KEY. Generate one with:

    python -c "import secrets; print(secrets.token_urlsafe(50))"

Paste the output after SECRET_KEY= (no quotes around it).

Leave this line exactly as it already is:

    DB_ENGINE=sqlite

That single line is what selects SQLite. You can ignore every MYSQL_* line in
the file - they are only read when DB_ENGINE=mysql, so you do NOT need the
Aiven credentials to work locally.

IMPORTANT - one more value you DO need: KMM_MASTER_KEY.
Ask Razeen for the team's value and paste it into your .env. Every private
key and every integrity tag is derived from it, so if yours differs from
everyone else's you will not be able to read shared encrypted data, and if
you leave it blank your own data stops decrypting the moment you restart
the server.

.env is gitignored. It is your own file and never gets committed.


================================================================================
STEP 6 -- Create the database
================================================================================
    python manage.py migrate

This creates db.sqlite3 in the project folder and builds all the tables. You
should see a long list of lines ending in "OK". That file is gitignored, so
your local data is yours alone and can never conflict with anyone else's.


================================================================================
STEP 7 -- Load the accounts and sample data
================================================================================
    python manage.py seed_demo

A brand-new database has zero users, so without this you can't log in to
anything. This creates the team's standard logins plus sample friends, posts,
likes, comments, messages and reports, so there's actually something to look
at.

It is safe to run again at any time - it tops up what's missing instead of
creating duplicates.

Accounts it creates:

    ROLE                          USERNAME                      PASSWORD
    ---------------------------------------------------------------------
    Standard User                 alice, bob, carol             demo12345
    Developer                     Razeen, Afnan, Munia          1234
    Admin                         razeen_admin                  123

    Everyone logs in at the SAME page: /accounts/login/

There is one login page for everybody. Your account's single role decides
where you land after signing in and what you may do - Standard Users get the
social site, Admins the admin panel, Developers the developer panel. Admin
and Developer accounts have no access to the social site at all; that
separation is deliberate (see the HIERARCHY section in todo.txt).


================================================================================
STEP 8 -- Run the server
================================================================================
    python manage.py runserver

Then open this in your browser:

    http://127.0.0.1:8000/accounts/login/

Log in as alice / demo12345. You should land on the feed and see three posts.
Stop the server with Ctrl+C.

Try these too, to confirm everything works:
    - log in as razeen_admin / 123                  -> admin panel + reports
    - log in as Razeen / 1234                       -> developer raw-DB viewer


================================================================================
STEP 9 -- Confirm which database you're on
================================================================================
    python manage.py dbinfo

You should see:

    Backend: SQLite (local file)
      File:     ...\db.sqlite3
      Scope:    local to your machine - nobody else sees your data
    Connection: OK
    Migrations: up to date

Run this any time you're unsure which database you're pointed at.

Setup is done. Open todo.txt and find your section.


================================================================================
EVERYDAY USE (after setup)
================================================================================
Each time you sit down to work:

    1. activate the venv   (see step 3)
    2. git pull
    3. python manage.py migrate     <- in case a teammate added a migration
    4. python manage.py runserver


================================================================================
IF SOMETHING GOES WRONG
================================================================================
"no module named django"
    Your virtual environment isn't activated. See step 3.

"no such table: ..." or the site 500s on every page
    You skipped step 6. Run: python manage.py migrate

Can't log in / no accounts exist
    You skipped step 7. Run: python manage.py seed_demo

You changed .env and nothing happened
    Django's auto-reloader only watches .py files, not .env. Stop the server
    (Ctrl+C) and start it again.

Port 8000 already in use / your changes don't show up
    An old server is still running. Kill it:
        Windows       :  netstat -ano | findstr :8000    then  taskkill /PID <pid> /F
        macOS / Linux :  lsof -i :8000                   then  kill -9 <pid>

pip install fails while building mysqlclient
    Use requirements-sqlite.txt (step 4). You don't need mysqlclient for
    SQLite work.

You want to start over with a clean database
    Delete db.sqlite3, then run migrate and seed_demo again. Nothing is lost
    that anyone else depends on - it's your local file only.

Anything else
    python manage.py check      catches most configuration and model mistakes
    python manage.py dbinfo     shows the active database and its state


================================================================================
SWITCHING TO THE SHARED AIVEN DATABASE
================================================================================
You need this for the PROJECT DEMONSTRATION, or any time you specifically
want to work against the shared team data. Day to day, stay on SQLite.

    1. Install the MySQL driver, if you used requirements-sqlite.txt:
           pip install -r requirements.txt

    2. Ask Razeen for the Aiven credentials (they are deliberately not
       written down anywhere in this repository).

    3. In your .env, change:
           DB_ENGINE=mysql
       and fill in MYSQL_DATABASE, MYSQL_USER, MYSQL_PASSWORD, MYSQL_HOST,
       MYSQL_PORT. Keep MYSQL_SSL_MODE=REQUIRED - Aiven needs it.

    4. Restart the server (the .env change is not picked up automatically).

    5. Confirm with: python manage.py dbinfo

Switch back by setting DB_ENGINE=sqlite again. Your SQLite file is untouched
while you're on MySQL and vice versa, so you can move between them freely.

WARNING: on mysql you are writing to the database the whole team and the
demonstration share. Anything you delete, everyone loses. Do NOT run
seed_demo against it (it refuses by default, for exactly this reason).


================================================================================
IMPORTANT -- MIGRATIONS STILL HAVE TO REACH MYSQL
================================================================================
Working on SQLite does not change how migrations work, but remember:

    - If you change a model, run `python manage.py makemigrations` and COMMIT
      the generated file in <app>/migrations/. That file is how your change
      reaches everyone else and the Aiven server.
    - A migration applied to your SQLite file is NOT applied to Aiven. Before
      the demonstration, someone must switch to DB_ENGINE=mysql and run
      `python manage.py migrate` there. Check with `python manage.py dbinfo`,
      which reports any unapplied migrations.
    - Never commit db.sqlite3 (it's gitignored already - leave it that way).
